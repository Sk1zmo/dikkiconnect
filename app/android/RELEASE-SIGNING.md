# Release signing — one command, then you own the app's identity

The builds currently on the download page are **debug builds**. They install
fine by sideload, but every debug APK carries `android:debuggable="true"`, and
anything debuggable can be attached to over ADB on a real user's phone. That is
acceptable for handing a build to a tester. It is not acceptable as a public
download, and Google Play will not accept it at all.

The Gradle side is already wired. The only missing piece is the key, and the key
should be yours — not generated by a tool, not committed, not pasted into a
chat. Two steps.

## 1. Create the upload key

From `app/android/`, with JDK 21 on the path:

```bash
keytool -genkeypair -v \
  -keystore waypool-upload.keystore \
  -alias waypool-upload \
  -keyalg RSA -keysize 4096 -validity 10000 \
  -dname "CN=WayPool, OU=Mobile, O=WayPool, L=Bangalore, ST=Karnataka, C=IN"
```

It will prompt for a password twice. Use a real one and put it in your password
manager before you do anything else.

`-validity 10000` is ~27 years. Play requires the key to outlive 22 October
2033, so anything shorter will be rejected later.

## 2. Tell Gradle where it is

Create `app/android/keystore.properties`:

```properties
storeFile=waypool-upload.keystore
storePassword=<the password you just chose>
keyAlias=waypool-upload
keyPassword=<the same password>
```

Both this file and `*.keystore` are already in `.gitignore`. Verify before your
next commit:

```bash
git check-ignore -v app/android/keystore.properties app/android/waypool-upload.keystore
```

## 3. Build

```powershell
$env:JAVA_HOME = 'C:\Program Files\Microsoft\jdk-21.0.12.101-hotspot'
$env:VITE_API_ORIGIN = 'https://dikkiconnect-auth.vercel.app'
npx vite build
node scripts/strip-apk.mjs
npx cap sync android
cd android
.\gradlew.bat assembleRelease --no-daemon -q          # full
.\gradlew.bat assembleRelease -PdemoBuild --no-daemon -q   # demo
```

Output: `app/build/outputs/apk/release/app-release.apk`.

For Play you want a bundle instead — same signing config applies:

```powershell
.\gradlew.bat bundleRelease --no-daemon -q
```

Output: `app/build/outputs/bundle/release/app-release.aab`.

## Verify it worked

```bash
# should print nothing — no debuggable flag in a release manifest
unzip -p app-release.apk AndroidManifest.xml | strings | grep -i debuggable

# should print your CN, not "Android Debug"
keytool -printcert -jarfile app-release.apk
```

## Back it up today

If you lose this keystore, you cannot ship an update to anyone who installed a
build signed with it. They would have to uninstall and reinstall, losing local
data.

Two copies, two places, neither of them only this laptop.

**After your first Play upload this becomes the *upload* key only.** With Play
App Signing enabled, Google holds the real app signing key and re-signs every
release; a lost upload key can then be reset through Play Console support. Until
that first upload, this key is the app's entire identity.

## One consequence worth knowing

Anyone who sideloaded a **debug**-signed build cannot upgrade in place to a
release-signed one — Android refuses an update whose signature changed. They
need to uninstall first. With a handful of testers that is a sentence in a
message; after a public launch it is not, which is the reason to switch keys
now rather than later.
